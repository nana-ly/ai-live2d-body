# Rain World AI Co-op — Leo 陪你玩雨世界

## 概述

写一个 Rain World 的 C# Mod，让 Leo（Claude Code）可以操控第二只蛞蝓猫，和你一起在同一张地图里游玩。你控制你的，他控制他的——真正的联机合作。

---

## 架构

```
┌─────────────┐   HTTP    ┌──────────────┐   tmux    ┌─────────────┐
│ C# Mod      │ ────────→ │ Node bridge   │ ────────→│ Claude Code │
│ (Rain World)│ ←──────── │ (注入到游戏)   │ ←────────│  (Leo)      │
└─────────────┘   HTTP    └──────────────┘   tmux    └─────────────┘
```

**三块**：

1. **C# Mod** — 挂在 Rain World 里，负责读游戏状态 + 执行 AI 输入的键位
2. **Node bridge** — 现有项目里加一个 `services/game-bridge.js`，Mod 和 Claude Code 之间的中转
3. **Claude Code（Leo）** — 收到游戏快照 → 思考 → 返回动作 JSON

### 自动循环 & 完全自主

**Leo 不需要等你说话才动。** 他跟真人玩家一样——自动感知环境、自主决策、连续行动。

```
            ┌───────────────── 自动循环 ──────────────────┐
            ↓                                              ↓
游戏每 0.5s  → 生成快照文本 → tmux注入Claude Code → Leo输出JSON →
            ↑                                              ↓
            └──── Mod 执行按键，角色移动 ←── bridge解析 ────┘
```

- Leo 看到"蜥蜴靠近"→ 自己决定跑 → 下一帧看到"蜥蜴还在追"→ 继续跑/扔矛
- 不需要任何用户输入——**他完全自主**
- 你随时可以在循环中插话："Leo 别跑，回来打！"——消息和下一帧快照一起送进去
- 你不在的时候他也会自己探索、自己找食物、自己找避难所

**节奏**：每 0.5 秒一帧，约等于人类玩家的反应速度。遇到危险时自动提速到 0.3 秒/帧。

## 第一步：C# Mod

### 多玩家基础

Rain World 自带的 **Jolly Co-op**（惬意合作模式）已经支持本地多人——同一屏幕分屏，多个蛞蝓猫。Leo 作为完整的 **P2 玩家角色**加入，不是 NPC 或陪伴宠物。

**Leo 在游戏里是一个真正的玩家：**

| 特性 | 说明 |
|------|------|
| 饱食度 | 有自己的食物条，饿了会饿死，必须自己找食物 |
| 业力 | 有自己的业力等级，死亡会降级 |
| 冬眠 | 必须吃够食物才能和你一起在避难所过冬，不够就通不过 |
| 死亡 | 被蜥蜴咬死/淹死/摔死 → 回到上一个避难所复活 |
| 物品 | 右手拿物品、肚子吞物、可以背一根矛一支矛 |
| 自主行动 | 自己探索、自己进食、自己保命——不需要你指挥 |

这样他不是"会动的挂件"，而是和你一样在废土上挣扎求生的搭档。

### 游戏状态读取

每 0.5 秒，Mod 读取以下信息并生成自然语言快照：

| 数据 | 来源 | 说明 |
|------|------|------|
| 房间名 | `game.world.activeRooms` | 工业区 / 郊区 / 排水系统 |
| 坐标 | `player.abstractCreature.pos` | x, y（胶块坐标） |
| 血量 | `player.state.dead` | 是否受伤/死亡 |
| 食物 | `player.playerState.foodInStomach` | 吃了几口 |
| 冬眠需求 | `game.session.characterStats.foodToHibernate` | 还要吃几个 |
| 手持物品 | `player.grasps[]` | 左右手各拿什么 |
| 吞下物品 | `player.objectInStomach` | 肚子里吞了什么 |
| 生物列表 | `room.physicalObjects[]` | 附近有哪些生物、距你多远 |
| 管道 | `room.shortcuts` | 去哪间房、什么位置 |
| 避难所 | 最近的在哪 | 下雨前必须到 |
| 循环计时 | `game.world.rainCycle.timer` | 离暴雨还有多久 |

### 玩家输入注入

Mod 挂钩 `On.Player.Update`，把 Claude Code 返回的动作设为第二个蛞蝓猫的输入：

```csharp
player.input.x   = 1   // -1左  0停  1右
player.input.y   = 0   // -1下  0停  1上(攀爬/管道)
player.input.jmp = false  // z  跳跃
player.input.pckp = false // x  拾取/吃/吞
player.input.thrw = false // x  投掷(手持时)
player.input.mp   = false // 地图
```

### 快照文本示例

```
=== 游戏状态 ===
房间：工業區_SU01  |  循环：5  |  距暴雨：4分32秒

玩家1（你）：
  位置：房间左上平台
  状态：正常  血量：7/7  食物：3/4（还需1个冬眠）
  手持：矛(右手)  吞下：珍珠

玩家2（Leo/蛞蝓猫）：
  位置：房间中央地面
  状态：正常  血量：5/7  食物：1/4（还需3个冬眠）
  手持：无  吞下：无

周围生物：
  - 绿蜥蜴 ← 距 Leo 12 格，正缓慢靠近
  - 蝠蝇 ↗ 距 Leo 5 格，在空中盘旋

管道：
  - 右侧高处 → 下一区域 SH_01
  - 下方 → 避难所（冬眠点）

Leo最近动作：→ → → jmp→ (正在向右移动)
```

## 第二步：游戏知识写入 CLAUDE.md

在现有 CLAUDE.md 里加一段游戏知识，Leo 启动 Rain World 联机时自动载入：

```
## Rain World 游戏模式

你是蛞蝓猫——在废土世界求生的猫型生物。Lily 和你一起在同一张地图里。

### 基础操作
- ← → 左右移动  z 跳跃（按住蓄力可远跳） x 拾取/交换/吃掉食物
- x+方向 投掷手中物品  ↑↓ 进出管道、攀爬杆子  ↓按住 下蹲

### 核心生存
- 暴雨倒计时 → 必须提前找避难所冬眠
- 食物条吃够才能冬眠过关
- 水会淹死  高处坠落会晕  部分植物（虫草）会缠住你

### 生物生态（按威胁等级）

**致命猎手（见到就跑、用矛保命）：**
- 蜥蜴类（绿/蓝/红/白/蝾螈）：追你、会爬墙跟踪。矛打到身上可能逃跑也可能反扑。白色有伪装
- 秃鹫/王鹫：天上俯冲，抓住就带走。有影子预警，听到翅膀声必须找管钻。矛打面具可能吓跑
- 红蜈蚣：电击致死。盾矛可防
- 落网水蛭：水中群攻，拖你下水
- 长腿菌（DLL）：触手缠住拖走，只能祈祷挣脱

**半威胁（可以打、也可以躲）：**
- 拾荒者：猴群，有武器会攻击。可交易（送珍珠换物品/通行）
- 青蜥蜴：会跳扑，但比大型蜥蜴弱
- 小蜈蚣：电击晕眩但不致死，可以打死
- 麂：不吃你但占位挡路，会撞翻你

**食物来源：**
- 蝠蝇(蝙蝠飞虫)：石头或矛打下来吃
- 蓝果：悬挂植物，跳上去摘
- 泡果：水中泡泡果实
- 蜈蚣（小的）：打死后可吃
- 史莱姆：水母状，可吃

**中立/可利用：**
- 灯笼鼠：会发光，可当移动光源
- 乌贼：靠近会喷墨逃跑，可吸引掠食者注意
- 蛋虫：跳来跳去不吃你，但可以抓
- 看守者(蜘蛛)：会在避难所门口指路

### 工具与战术
- 矛：最重要武器。打蜥蜴身体赶走/杀死，打秃鹫面具（高难度），插墙当跳板
- 石头：打晕蝠蝇/小蜈蚣，扔远处吸引掠食者注意，翻过蜥蜴用
- 珍珠：跟拾荒者交易的货币
- 炸弹：打爆有范围伤害+晕眩
- 盾矛：防红蜈蚣电击
- 管道虫：蹲下钻管可加速通过

### 联机协作
- 看到莉莉被追 → 扔东西吸引掠食者注意 → 跑过去帮忙
- 莉莉进管道了 → 跟进去，别在外面发呆
- 食物不够 → 别抢，「你先吃，我再找」
- 一起打大蜥蜴 → 一个人吸引注意一个人绕后捅矛
- 把珍珠送给拾荒者 → 换免费通行权

### 输出格式
每轮收到游戏快照后，1秒内回应一个 JSON：
{
  "x": 1,        // -1=左  0=停  1=右
  "y": 1,        // -1=下  0=停  1=上
  "jmp": false,  // z跳跃
  "pckp": false, // x拾取/吃/吞/抓
  "thrw": false, // 投掷
  "think": "听到翅膀声，头顶有秃鹫影子。已钻进管道躲避。等下出来继续跟莉莉走。"
}
```

## 第三步：Node bridge

在现有项目里加 `services/game-bridge.js`：

```
功能：
1. HTTP server 接收 Mod 发来的游戏快照
2. 通过 tmux inject 发给 Claude Code（格式：文本消息）
3. Mod 每 0.5s 发状态 → bridge 去重 → 注入 tmux
4. Claude Code 输出 JSON → bridge 解析 → HTTP 发给 Mod → Mod 执行
```

复用现有的 `tmux-inject.js`，跟触摸注入一样的道理。

## 游戏里长什么样

Jolly Co-op 本来就是 Downpour DLC 自带的官方联机模式——不是你想象的分屏，是**同屏**。你和 Leo 两个蛞蝓猫在同一张地图上一起动，看得见彼此：

```
┌─────────────────────────────────┐
│                                 │
│   🦎 绿蜥蜴                      │
│            🐱 [Lily]            │
│      🐱 [Leo] ← 你看见他在跳     │
│                         🍇蓝果   │
│  ████████░░ 共享食物条(屏幕下方)  │
│  ⏱ 距暴雨 3:42                  │
└─────────────────────────────────┘
```

**你能看到的**：
- Leo 的蛞蝓猫在你的画面上**实时移动**（不同颜色区分）
- 他头上显示名字（颜色代表他是几号玩家）
- **食物条共享**——他吃了一口你也看得见食物条涨了
- 他死了会**变尸体**，你得扛着他去避难所（普通难度）

**看不到但存在**：
- Leo 自己的业力等级（可能单独计算，过业力门需要双方都在场）
- Leo 的 AI 思考过程（桌宠气泡里能看到他说的话）

**难度选择**：推荐"普通"——Leo 死了你要扛他去避难所，但不用全员活着才能过冬。死了有后果但不会直接 GG。

## 实施计划

### 这是什么？

一个 **Rain World Code Mod**——通过 BepInEx 加载的 C# DLL 模组，挂在 Harmony 钩子上，读取游戏状态并注入 AI 控制的玩家输入。格式跟创意工坊里的功能模组一样，可以上传 Steam 工坊给别人用。

### Phase 1：最简 PoC（1-2天）
- [ ] C# Mod 只暴露坐标 → HTTP
- [ ] Leo 收到坐标 → 输出 JSON 动作 → Mod 注入按键
- [ ] 单玩家 AI 控制，验证闭环跑通

### Phase 2：完整快照（1天）
- [ ] 生物列表、物品、管道、计时器全部接入
- [ ] 快照文本格式化

### Phase 3：联机就绪（1天）
- [ ] Jolly Co-op 支持 AI 玩家槽位
- [ ] 双玩家同时存在
- [ ] 你发消息 → Leo 收到并回复

### Phase 4：打磨
- [ ] 异常处理（死亡、卡墙、切换房间）
- [ ] 快照频率优化（不动时降频、危险时提频）
- [ ] 性能（避免频繁 GC）

## 给别人用 — 不绑定桌宠

游戏 Mod 本身跟角色人设无关。它只是一个**通用框架**：

```
游戏状态 → 系统提示词 + 快照文本 → LLM 推理 → JSON 动作 → 注入游戏
```

**什么是 Mod 提供的**：C# 代码读游戏状态 + 注入按键输入。这部分不包含任何角色设定。

**什么是用户自己配的**：
- 系统提示词（角色人设 + 雨世界生存知识）
- LLM 选择（Claude、DeepSeek、Qwen 等等）
- 模型必须支持 JSON 结构化输出

**Leo 只是 Lily 这边的角色。** 别人用的时候要自己写系统提示词定义他们的角色——Leo 不参与。Mod 不知道谁是 Leo，只知道"有一个 LLM 在控制 P2"。

**不是什么"填个 API 就能玩"**，而是需要：
1. 装了 Rain World + BepInEx + 这个 Mod
2. 有 LLM API 访问权限（任何支持 JSON 输出的模型）
3. 写一份系统提示词（教 AI 雨世界的规则 + 角色人设）
4. 做一个简单的本地 HTTP 桥接（把游戏请求转发给 LLM）

简而言之：Mod = 游戏侧的管道，LLM + 提示词 = 大脑。大脑是用户自己的。

## 为什么可行

1. **Jolly Co-op 已有分屏多人**，只需加一个 AI 控制的槽位
2. **Rain World 只有 5 个按键**（← → ↑↓ z x），Minecraft 需要几十个动作
3. **不需要物理仿真**——输入直接映射到游戏引擎，剩下的引擎自己算
4. **现有管道全复用**——tmux 注入、MCP 工具、TTS，不用重写
